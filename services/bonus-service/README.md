# Bonus Service

Python 3.13.15, FastAPI, Pydantic v2, uv. Сервис работает на порту 8050.
На этом этапе PostgreSQL, SQLAlchemy и Alembic не подключены.

## Запуск из корня монорепозитория

```bash
uv sync --all-packages
uv run --package bonus-service python -m bonus_service.main
```

Настройки: `BONUS_HOST` (по умолчанию `0.0.0.0`) и `BONUS_PORT` (8050).
Swagger UI: http://localhost:8050/docs.

## HTTP API

Все внутренние запросы требуют `X-User-Name`. Эти маршруты вызывает Gateway.

| Метод | Маршрут | Результат |
|---|---|---|
| GET | `/manage/health` | 200, `{"status":"UP"}` |
| GET | `/internal/v1/privilege` | 200, счет и история |
| PUT | `/internal/v1/privilege/operations/{ticketUid}` | 201 при покупке, 200 при повторе |
| PUT | `/internal/v1/privilege/operations/{ticketUid}/reversal` | 200, баланс и статус после возврата |

Пример тела покупки: `{"price":1500,"paidFromBalance":false}`.
Новый счет: BRONZE, баланс 0. Оплата деньгами начисляет `price // 10`.
Оплата бонусами списывает `min(balance, price)` и не начисляет новые баллы.
При возврате восстанавливаются списанные бонусы либо снимаются начисленные,
но баланс не становится отрицательным. Обратная операция сохраняется в истории.
Даже операции с нулевой суммой регистрируются для защиты от повторов.

Один UUID билета обозначает одну покупку. Повтор покупки возвращает сохраненный
результат, включая баланс на момент покупки. Измененное тело или повтор покупки
после возврата — 409. Чужая или отсутствующая операция — 404. Повтор возврата
не меняет баланс и возвращает текущее состояние счета. Ошибки валидации — 400.
Полный контракт находится в корневом `openapi.yaml`.

## Архитектура

- `domain`: неизменяемые модели и чистые функции расчета бонусов.
- `application`: сценарии и Protocol-интерфейсы репозитория, Unit of Work и часов.
- `infrastructure`: хранилище в памяти с транзакциями и системные часы.
- `presentation`: FastAPI-маршруты и преобразование Pydantic DTO.
- `main.py`: сборка зависимостей и запуск.

Unit of Work атомарно сохраняет счет, историю и результат покупки.
Изменения до commit изолированы и отбрасываются при ошибке. Блокировка сериализует
конкурентные операции в одном процессе. Для подключения PostgreSQL потребуется
реализовать существующие интерфейсы с локальной транзакцией БД, ограничениями
уникальности и блокировкой счета; HTTP-слой и бизнес-правила менять не требуется.

**Ограничение текущего этапа:** данные теряются при перезапуске. Запускать один
worker и один экземпляр сервиса: хранилища разных процессов не синхронизируются.
Проверки HTTP выполняются через ASGITransport без сетевого сервера и внешних сервисов.
